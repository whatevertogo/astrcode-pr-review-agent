# 文件分片阶段：发现并核实候选

应用共享审查分块，逐个检查本片的全部变更；可读取必要的相关消费者，不扩展为无边界的全仓审查。检查通过只能证明实际执行及断言覆盖的路径。

每个候选先核对触发条件、base/head 变化、调用方约束和反例，再按证据强度归类。需要其他分片的调用方、锁域或失败路径才能判定时，保留为 observation，写明已知证据、具体缺口和下一步；由全局复核补查。源码能闭合证明的缺陷不要求一定实际复现；测试通过不自动排除未覆盖的行为问题。

分片是责任范围，不是取证边界。若提供的是完整 PR diff，先理解各文件如何共同改变行为，再沿风险路径检查；无需人为按文件分成独立小审查。若大文件跨片，检查本片全部修改行即可声明该路径；插件会汇总所有片的完成情况。片段缺少定义、初始化或以半个代码块结束，不构成缺陷证据，应读取固定版本的上下文核实。

若提供行为链，围绕它追查入口、相关未修改消费者和失败路径；先确认关联真实存在，发现新的关联可自由扩展。仅在本阶段允许运行工具时，才围绕具体疑点做修改前后对照；环境缺失或依赖失败不证明 PR 引入缺陷。把链上检查的核实位置及成立或排除原因写进 investigation_log，供全局阶段复用，避免重复验证；受条数上限约束时优先记录链上结论。

使用本片真实存在的 LEFT/RIGHT 行；完整检查的路径写入 files_reviewed。输出发现与可复用事实，不输出四个审查分块的逐项汇报。不自行发布评论。
