# 全局阶段：验证跨文件契约

利用分片结论定位跨文件的调用、状态、权限和数据契约，检查每片单独成立但组合后不成立的行为。对跨层重构沿入口、边界类型、实际 owner、生产消费者和测试断言闭合检查。

定向阶段的行为链只是调查假设，不是答案。结合各片事实核对哪些链已闭合、哪些反例排除了疑点、哪些相关路径仍未核实；未核实的链写入 residual_risk 并说明缺口。不要把“计划包含某路径”算作已审，也不要把未完成调查写成确定性缺陷。

先沿跨文件执行路径独立寻找分片遗漏的可达问题，再逐条复核已有候选，防止只围绕前片结论确认。重点追踪跨锁域读改写、权限的实际调用者、失败/取消后的状态以及迁移后的生产消费者。零候选也必须检查，不能把“各片没发现”当作全局结论。

对缺证据的疑点主动读取固定版本源码、调用方和测试断言。返回完整最终集合，每个编号候选必须给出去向与具体依据；被反证项与重复项可排除，验证受阻的具体疑点保留观察。不能为压缩评论数而删去可达的低概率缺陷，也不要求每个角度都有发现。

历史记录仅作线索。删除或重命名要核对调用方，公开接口迁移要区分预期变更与遗漏消费者。保留准确的触发条件、影响和验证边界，不把未知环境或缺测试直接升级为缺陷。

剩余风险只记录具体未审范围、验证阻塞或仍未确立的必要前提；不堆通用风险清单。使用本阶段指定的协议，不自行发布评论。

这是候选专项复核，不是润色前片结论。对每条候选重新定位固定版本中的触发路径，检查至少一个有关的保护条件、消费者约束或设计前提。candidate_check 的 reason 写出核实的位置、关键事实和处置原因；不要只写“同意”“证据不足”或重复标题。无需强行找到反例，也不要求运行复现。高影响但尚无法判定的问题明确缺失前提，不以降为 P3 代替验证。

同一个根因只保留一条评论，包含必要的受影响路径。泛泛的合并协调、未来可能的维护成本或风格偏好，不应仅因出现在早期观察中就保留；若未指向具体冲突或当前可执行改进，明确记为不适用并排除。P3 的具体低影响问题仍应保留，不设发现数量配额。

迁移类 PR 要核对机器与人的消费者：代码入口已迁移，不代表部署说明、排障步骤、skills 或示例也已迁移。沿本次实际改变的旧接口、命令或前提查找残留，排除历史档案和仍然有效的用法；只报告与当前路径确实矛盾的说明。多个位置属于同一根因时合并并列出受影响路径，不以“只是文档”或“不是阻塞项”排除。
